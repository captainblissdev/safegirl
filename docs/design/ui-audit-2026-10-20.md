# UI audit, 20 October 2026

An audit of the SafeGirl interface as it stands on `development`. No app
code, knowledge-base content, threshold or Safety Net pattern was
changed. Every screenshot, report and measurement named below is in
[`audit-2026-10-20/`](audit-2026-10-20/).

## 1. Method and environment

**Code audited:** `development` at `4ca85d6` (Merge pull request #47).
The audit branch `design/ui-audit` adds only these documents.

**Running system.** Three local processes, as in the README:

- `ml_service` on 127.0.0.1:8001 (checkpoint v3, 21 KB entries).
- The gateway on 3001, started with `AUTH_DISABLED=true` and
  `NODE_ENV=development` on the command line. The relevance gate and
  both classifier thresholds were left at their defaults (gate off,
  0.35 and 0.5).
- A production build of the interface (`vite build`, written outside the
  repository), served by `vite preview` on 4173. It forwards `/api` to the
  gateway.

**Browser.** Headless Chrome 155 driven by puppeteer-core 23.11.1.
Viewports: 360×740 (mobile, touch) and 1280×800.

**Firebase.** The interface signs in anonymously before every online
query. In the test browser that sign-in was answered with a synthetic
token, so no request reached Firebase. The gateway accepts the token
because authentication is disabled. The **error state** was produced by
making that stubbed sign-in fail. **Limited mode** was produced by
stopping the gateway, so the preview proxy could not reach it.

**Queries.** All queries are synthetic:

| Screenshot | Query | What the system did |
|---|---|---|
| answer-scoped | "Which birth control methods can a teenager use?" | contraception ≥ 0.5, scoped, KB-C3 |
| answer-unscoped | "Am I okay?" | pregnancy 0.485, unscoped, KB-S4 |
| reply-abstain | "hmm" | contraception 0.302, below 0.35, no retrieval |
| reply-help | "Help" | generic help rule, signposting |
| referral | "someone touched me" | Safety Net, abuse referral |

**Measurements.**

- **Lighthouse mobile:** Lighthouse 12.3.0 for performance, accessibility,
  best practices and SEO. Lighthouse 11.7.1 for PWA, because 12 removed
  that category. Both used simulated throttling and the default
  412×823 mobile emulation, with Google API hosts blocked. Lighthouse
  scores the first screen only (the disclaimer).
- **Accessibility:** axe-core 4.10.2 (WCAG 2.0–2.2 A/AA and best practice)
  on seven screens at both widths. I also measured:
  - the rendered size of every control;
  - a Tab walk through each screen, recording the focus style at each stop;
  - live regions;
  - reflow at 320 CSS px, and 200% zoom at 360 px (a 180 CSS px viewport
    at DPR 2);
  - computed animations with and without `prefers-reduced-motion`.
  
  Contrast ratios for colour pairs that axe could not resolve (gradients)
  were calculated from the theme tokens in `index.css`.
- **Reading level:** Flesch reading ease and Flesch–Kincaid grade, with a
  heuristic syllable count. Scores are indicative to about ±1 grade.

**Evidence files:**

## 2. Nielsen's 10 heuristics

Rating: **Good** (no change needed), **Fair** (works, with real
problems), **Poor** (problems a user will hit on a normal visit).

| # | Heuristic | Rating | Evidence |
|---|---|---|---|
| 1 | Visibility of system status | Fair | Good: typing dots while waiting (`typing-*`), a limited-mode notice (`limited-mode-*`), and an offline banner (in `App.tsx`; not captured). Bad: at 360 px the input is pushed below the fold after the first answer (`answer-scoped-360`, `conversation-3-360`). The sign-in error banner is below the fold at **both** widths (`error-state-360`, `error-state-1280`; measured bottom 773 px of 740 and 817 px of 800). Nothing shows whether an answer matched well, loosely or not at all. |
| 2 | Match between system and the real world | Fair | Screens are plain English (disclaimer grade 0.9, chat greeting 3.5). KB answers have a median grade of 10.0, ranging from 5.3 to 15.8 (`reading-level.csv`). Terms like "youth-friendly services", "dual protection" and "post-exposure prophylaxis" are not explained. "Help" is answered with "I don't have information on that yet." (`reply-help-*`). |
| 3 | User control and freedom | Fair | Chips and suggestions only fill the input and never send, so the user can edit first. Escape closes the help dialog. "New chat" exists only at 1024 px and wider (`empty-chat-1280` vs `empty-chat-360`). On a phone, the only way to clear the conversation is "End session". |
| 4 | Consistency and standards | Fair | The chip labelled "STI" inserts "can chlamydia be cured" (`starter-chips-*`). Example questions mix sentence case with a "?" and lowercase without one. Scoped, unscoped, abstain and signposting replies share one bubble style (`answer-scoped`, `answer-unscoped`, `reply-abstain`, `reply-help`). The header says "Need help now?" and the side panel says "Need more support?" for the same content. |
| 5 | Error prevention | Good | Send is disabled while the input is empty. The input and chips are disabled while waiting (`typing-*`). Chips never auto-send. |
| 6 | Recognition rather than recall | Fair | Chips and suggestions help a user start. But the answer never shows which question it answers, so the user cannot tell "Am I okay?" was matched to an STI-symptoms question (`answer-unscoped-*`). The greeting's scope line disappears after the first question. |
| 7 | Flexibility and efficiency of use | Good | Enter sends. Every control is reachable by Tab. Suggestions save typing. |
| 8 | Aesthetic and minimalist design | Good | Calm and uncluttered at both widths. Minor: at 1280 px the help numbers appear twice (side panel and header dialog), and the disclaimer says "safe" twice. |
| 9 | Help users recognise, diagnose and recover from errors | Poor | The abstain reply to "hmm" gives the GBV helpline and Childline, with no "I didn't understand" and no prompt to rephrase (`reply-abstain-*`). The sign-in error is clear but off-screen (`error-state-*`). After an abstain no suggestions are offered, so there is no way forward except typing again. |
| 10 | Help and documentation | Fair | "Need help now?" is on every screen (`help-dialog-*`). There is no "what can I ask?" guidance once the greeting has gone. |

## 4. Where the assistant looks canned

1. **No matched question above the answer.** The reply to "Am I okay?" is
   KB-S4's answer, "It could be. Unusual discharge, genital sores or lower
   belly pain can be signs of an STI…", with nothing to say it answers
   "I have unusual discharge… Could it be an STI?" (`answer-unscoped-*`).
2. **Answers that only make sense after their own question.** Five KB
   answers begin "Yes", "No" or "It could be" (KB-C4, C5, S3, S4, P1).
   Shown under a different question, they read as a confident reply to
   whatever the user asked.
3. **Identical suggestions after every answer in a category.**
   "You could also ask" is a fixed list per category (`uiText.ts`). It
   leaves out only the exact question just asked. It is shown after loose
   matches too: "Am I okay?" is followed by "what is PrEP" and "can
   chlamydia be cured" (`answer-unscoped-1280`). It can also suggest a
   paraphrase of the question just answered. "Do I still need a condom if
   I have the implant?" gets KB-C4 and is then offered "Do I need a condom
   if I am on the pill?", which leads to the same entry.
4. **One reply style for every outcome.** Scoped (classifier sure),
   unscoped (classifier unsure), abstain and signposting replies all use
   the same white bubble. Only the hidden details line (`?details=1`)
   shows the difference.
5. **The abstain reply ignores what was said.** "hmm" gets the GBV helpline
   and Childline (`reply-abstain-*`): no "I didn't catch that" and no
   suggestions.
6. **The help reply contradicts itself.** "Help" gets "I don't have
   information on that yet." before the help numbers (`reply-help-*`).
7. **Suggestions look like raw logs.** They are copied verbatim from the
   evaluation set, so most are lowercase with no question mark ("what is
   PrEP", "is the clinic confidential").
8. **Verbatim repeats.** The same question always gets the identical
   paragraph. KB-C1 and KB-C2 are the same answer apart from one sentence,
   so two different questions get near-identical replies.
9. **Limited mode is four fixed sentences.** Offline, every non-safety
   message gets one of four category sentences. "Help" gets "Youth-friendly
   health services should provide respectful, confidential information and
   care…" (`limited-help-*`).
10. **No continuity between turns.** Each message is handled alone, so
    "Do I have it?" is answered with KB-S4 regardless of what came before.
11. **The source is hidden.** Each answer has an authoritative source (WHO,
    Kenya MoH), but users never see it. Showing it is the easiest way to
    look less canned and more trustworthy.
12. **Checked and not a problem: the typing state.** A typing indicator
    (three animated dots, `role="status"`, "Thinking…" for screen readers)
    appears while a reply is pending (`typing-*`).

## 5. The 13 starter questions

The interface has **4 starter chips** (Contraception, STI, Pregnancy,
Periods), each filling one question (`starter-chips-*`). Together with
the 12 "You could also ask" follow-ups (3 per category), it offers **13
distinct example questions**. All 13 are listed. Each is a verbatim
"clear" query from the retrieval development set.

| # | Question (verbatim) | Where | Verdict |
|---|---|---|---|
| 1 | Which birth control methods can a teenager use? | Contraception chip; contraception follow-up | OK |
| 2 | can chlamydia be cured | STI chip; STI follow-up | OK, but a narrow pick to represent every STI question, behind a chip labelled just "STI" |
| 3 | what are the danger signs in pregnancy | Pregnancy chip; pregnancy follow-up | **Jargon**: "danger signs" is MoH wording; a teen would say "warning signs" or "when should I worry" |
| 4 | is it normal for my period to be irregular | Periods chip | OK; "is it normal" is a stock opener, but it is the question teens actually ask |
| 5 | Do I need a condom if I am on the pill? | Contraception follow-up | OK |
| 6 | will the injection make me unable to have kids | Contraception follow-up | OK |
| 7 | what is PrEP | STI follow-up | **Generic**: a definition request that assumes the reader knows the acronym |
| 8 | is the HPV vaccine free for girls my age | STI follow-up | OK |
| 9 | can I go back to school after having a baby | Pregnancy follow-up | OK |
| 10 | should I take iron tablets when pregnant | Pregnancy follow-up | OK |
| 11 | how do I deal with period cramps | General follow-up | OK |
| 12 | what services can I get at a youth friendly clinic | General follow-up | **Generic, jargon**: institutional phrasing ("youth friendly clinic") |
| 13 | is the clinic confidential | General follow-up | **Generic**: "the clinic" has no referent in a first conversation |

Cutting across all 13: casing and punctuation are inconsistent (2 of 13
start with a capital and end with "?"). Questions 1–3 are both a chip and a
follow-up, so they can appear twice.

## 7. Offline mode

The interface switches to its offline pipeline (`offline/offlinePipeline.ts`)
in any of these cases: the device is offline, the request fails or times
out (20 s), sign-in cannot reach Firebase (10 s), or the gateway returns a
non-OK status other than 401. Every offline answer carries the
"Limited mode" notice.

- **"Help" offline:** the Safety Net does not flag it, so the keyword
  classifier labels it "general". The reply is the fixed sentence "Youth-friendly
  health services should provide respectful, confidential information and
  care. Ask a health worker what services are available."
  (`limited-help-*`). There is no generic-help rule offline (UI-07).
- **Safety phrase offline** ("someone touched me"): the referral screen,
  with the same abuse referral message and support options as online
  (`limited-referral-*` vs `referral-*`).
- **Does the Safety Net run offline?** Yes. `handleQueryOffline` calls
  `checkSafety` before anything else, and a flagged message is never
  classified. The gateway's `offlineSafetyParity.test.js` passes 9 of 9
  tests on this branch: the TypeScript copy flags the same 95 positive
  cases, passes the same 57 negative cases, and gives the same referral
  message per category.
- `offline/pipeline.ts`, a KB-based offline variant, is used only by its
  test, not by the app. It would answer "Help" with the period-pain entry,
  so it should not be wired in as it is.

## 8. What to fix in two days

In order, about 16 hours:

1. **UI-01:** show the matched question above every answer, and hedge
   unscoped answers (4 h).
2. **UI-02 and UI-03:** a real "I'm not sure what you mean" abstain reply,
   and drop "I don't have information on that yet" from the help reply
   (2.5 h).
3. **UI-04 and UI-05:** keep the input and the newest reply or error in
   view, and return focus to the input (4 h).
4. **UI-06:** contain focus in the help dialog and return it on Escape
   (1.5 h).
5. **UI-07:** add the generic-help rule to the offline pipeline, with a
   parity test (2 h).
6. **UI-09:** follow-ups only after scoped answers, never repeating the
   entry just shown (2 h).

UI-08 (reading level) should go to the clinical review in parallel; it
needs no developer time.
